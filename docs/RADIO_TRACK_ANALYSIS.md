# 예약 녹음의 곡별 자동 분리

예약 녹음의 원본을 보관하면서 PC에서 음악 구간을 찾아 곡별 FLAC 파일로 저장한다.
곡명·작곡가·연주자를 파일 태그에 기록하고, 불확실한 결과는 예약 화면에서 확인·수정한다.

## 사용 순서

1. 아래 방법으로 Windows PC에 분석 서비스를 설치·실행한다.
2. `local-analysis\connect.ps1`을 실행하면 설치된 라디오 앱을 우선 연결하고, 설치 앱이 없으면 기본 브라우저를 연결한다.
   설치 앱은 먼저 트레이 메뉴의 **종료**로 완전히 종료한다. 연결 도구가 앱을 열면 **2분 안에 오디오 시스템 보기**로 전환한다.
   브라우저만 연결하려면 `connect.ps1 -Browser`를 사용한다. 브라우저와 설치 앱의 연결 정보는 공유되지 않으므로 각각 최초 한 번 연결해야 한다.
3. 앱의 **편성표 → 예약 녹음 → 곡별 자동 분리 · PC 분석**에서 **PC 분석 서비스 연결됨**을 확인한다.
   서버 연결과 로컬 모델 준비가 확인된 기기에서만 곡 분리 패널과 예약별 버튼이 표시된다.
   연결하지 않은 Mac·휴대폰 등에서는 곡 분리 메뉴가 보이지 않으며 PC 서버에 접속을 시도하지 않는다.
   서버가 꺼지면 옵션을 숨기고 새 예약에는 곡 분리를 적용하지 않는다. 기존 예약·원본·전송 대기는 유지하며 서버가 돌아오면 다시 표시한다.
4. **새 예약에 곡별 자동 분리 적용**을 켠 뒤 예약한다. 기존 예약은 각 행의 **곡 분리 끔** 버튼을 눌러 켠다.
5. 예약 녹음이 끝나면 PC로 전송되어 순서대로 처리된다. 같은 패널에서 상태·곡 목록을 확인한다.
6. 곡별 미리 듣기·다운로드 또는 전체 ZIP 저장을 선택한다. 곡명·작곡가·연주자·시작/종료 초를 수정하면 파일과 태그도 다시 저장된다.

설치 앱에 최신 버전이 표시되는데 PC 기능이 없다면 앱 자체의 연결을 확인한다. 설치 파일 1.1.0은 그대로 사용할 수 있다.
PowerShell 실행 정책으로 스크립트를 실행할 수 없을 때는 정책을 바꾸지 않고 다음 명령을 실행한다.

```powershell
.\local-analysis\.venv\Scripts\python.exe local-analysis/connect_app.py --desktop
```

설정·브라우저 녹음은 유지한다. 연결 도구는 실행 중인 앱을 강제 종료하지 않으며 PC 서버 녹음도 중단하지 않는다.

예약마다 옵션을 저장하며, 녹음을 시작한 뒤 변경한 설정은 다음 녹음부터 적용된다.
상단의 Gemini 사용 여부와 전송 한도는 **새 예약**, 또는 기존 예약을 껐다 켤 때 적용된다.
녹음 중 스트림이 끊어져 저장된 각 파트는 독립 분석된다. 파트 사이에 잘린 곡은 확인이 필요하다.

## PC 서버 상시 녹음

**편성표 → 예약 녹음 → 곡별 자동 분리 · PC 분석 → PC 서버 상시 녹음**에서 설정한다.
서버가 설치·연결된 PC에서만 표시된다. 기본 선택은 KBS 1FM이며 기존 앱의 15개 채널을 함께 사용할 수 있다.

1. 채널을 하나 이상 선택하고 요일·시작·종료 시각을 정한다. 종일 녹음은 `00:00`~`24:00`이며 모두 한국 시간 기준이다.
2. 프로그램 이름을 비우면 해당 시간의 모든 방송을 녹음한다. 특정 프로그램만 원하면 편성표의 정확한 이름을 한 줄에 하나씩 입력한다.
3. **원본 + 곡별 FLAC** 또는 **원본만 저장**을 선택한다. 선택한 채널의 공통 설정을 **설정 저장·녹음 시작**으로 적용한다.
4. 채널별 **설정 불러오기**, **서버 녹음 켜기/끄기**, **녹음 설정 삭제**로 관리한다. 선택하지 않은 채널의 설정은 유지된다.

서버 상시 녹음은 브라우저 예약과 별개다. **앱을 닫아도 PC와 분석 서버가 켜져 있으면 계속된다.**
브라우저 TIMER 스위치와 관계없이 동작한다. 서버 녹음의 원본은 PC 작업 폴더에 M4A로 저장되고, 앱에서 내려받을 수 있다.
원본을 브라우저에 자동 복사하지 않는다. 같은 방송을 브라우저에서도 예약하면 두 개의 별도 녹음이 만들어진다.

재방송 제외는 현재 KBS 채널에 적용한다. 방송사의 `본방`·`재방` 구분을 사용하며, 편성 또는 구분을 확인하지 못하면
녹음을 대기하고 재조회한다. 다른 채널은 재방송 제외를 끄고 사용한다. 프로그램 선택이 없고 재방송 제외도 꺼져 있으면
편성표가 없어도 지정한 시간에 녹음한다. KBS의 24시 이후 방송일·자정 넘김과 주간 반복을 처리한다.

방송 종료 또는 파일 최대 길이(15~120분, 기본 120분)에 도달하면 파일을 마감하고 다음 구간을 녹음한다.
스트림은 재인코딩하지 않고 AAC 헤더를 정리해 5초 단위 조각을 가진 M4A에 저장한다. 원본 파일 경계에서 잘린 곡은 검토가 필요하다.
여러 채널은 독립적으로 녹음하고 완료된 파일의 곡 분석은 기존 GPU 대기열에서 순서대로 처리한다.
네트워크 단절 시 받은 구간을 보관하고 다시 연결하므로 중단 중의 방송을 소급 복구하지는 못한다.

설정은 PC의 `recorder.json`에 저장되어 서버·Windows 재시작 후 이어진다. 중단된 서버 녹음은 해당 원본을 쓰던
FFmpeg 프로세스인지 확인한 후 보관 가능한 구간을 복구한다. **진행 중 곡 분석**의 재시도 규칙은 아래 복구 설명과 같다.
서버 녹음을 끄면 진행 파일부터 마감하며, 이미 대기 중인 곡 분석은 계속한다.

원본·PCM·FLAC을 자동 삭제하지 않는다. 여유 공간이 8GB 미만이면 새 녹음을 대기하고,
녹음 도중 2GB 미만이면 해당 구간을 마감한다. 브라우저에는 남은 공간과 대기 작업 수가 표시된다.
Gemini의 기존 파일당 전송량·횟수 제한은 서버 녹음에도 똑같이 적용된다.

## Windows PC 설치

권장 대상은 NVIDIA RTX 4080 16GB, RAM 64GB PC다. Python 3.12, Git,
NVIDIA 드라이버와 `ffmpeg`·`ffprobe`가 PATH에 있어야 한다.
가중치 파일 합계 약 15GB 외에 CUDA 실행 환경과 중간 파일 공간이 추가로 필요하다.

저장소에서 PowerShell로 실행한다.

```powershell
.\local-analysis\setup.ps1
.\local-analysis\start.ps1
.\local-analysis\install-autostart.ps1
.\local-analysis\connect.ps1
```

설치 스크립트는 전용 `.venv`에 CUDA 12.8용 PyTorch 2.9.1과 Qwen3-ASR 의존성을 설치하고,
공식 MOSS-Audio 실행 코드와 두 모델의 가중치를 내려받는다. 기존 Python 환경을 변경하지 않는다.
설치에 사용한 모델·MOSS 실행 코드의 리비전을 고정하며, 분석 중에는 모델을 추가 다운로드하지 않는다.
서비스는 숨은 프로세스로 실행되며 **127.0.0.1:8766**에서만 듣는다.
`install-autostart.ps1`은 현재 사용자의 시작프로그램에 바로가기를 등록한다. 재부팅 후 Windows에 로그인하면 서버가 다시 실행된다.
자동 실행은 설치된 `pythonw.exe`로 `start_service.py`를 실행하므로 PowerShell 실행 정책을 변경하지 않는다.
자동 실행을 해제하려면 시작프로그램의 `Mad for Audio PC Analysis.lnk`를 제거한다.
연결 도구는 인증된 서버에서 2분 유효한 일회용 연결 코드를 발급받는다. 코드는 URL fragment로 전달되어
Pages 서버 요청에 포함되지 않으며 앱에서 즉시 주소에서 제거한다. 기존 연결 코드와 API 키는 링크에 넣지 않는다.
한 번 연결한 브라우저에서는 다음 방문부터 자동 연결한다. 다른 브라우저·프로필은 다시 연결해야 한다.
`127.0.0.1`은 앱을 실행하는 기기 자신이다. 이 설정은 **같은 PC의 브라우저용**이며 휴대폰·다른 PC에서 접근하는 원격 서버 주소가 아니다.
브라우저에서 로컬 네트워크 접근을 요청하면 허용한다. 사용 브라우저가 HTTPS 앱의
로컬 HTTP 접속을 차단하면 `http://127.0.0.1:8123`에서 앱을 서빙하여 이용할 수 있다.

설정과 데이터 기본 위치:

```text
%USERPROFILE%\.mad-for-audio\analysis\config.json
%USERPROFILE%\.mad-for-audio\analysis\models\
%USERPROFILE%\.mad-for-audio\analysis\jobs\<작업 UUID>\
```

사용자 폴더를 사용하므로 MSIX 앱의 LocalAppData 가상화 여부와 관계없이 같은 설정과 모델을 찾는다.

`MFA_ANALYSIS_HOME` 환경 변수로 데이터 폴더를 바꿀 수 있다. 설치·실행 시 같은 값을 사용한다.
`config.json`의 주요 값:

| 값 | 용도 |
|---|---|
| `token` | 브라우저와 PC 서비스 연결 코드. Gemini 키와 다른 값이다. |
| `geminiApiKey` | Google 직접 연결용 API 키. OpenRouter 키가 없을 때 사용한다. |
| `maxCloudSeconds` | 파일당 클라우드 전송 상한(기본 600초). 예약의 한도와 비교해 작은 값을 적용한다. |
| `modelPython` | 전용 CUDA Python 실행 파일 |
| `modelCache` | Hugging Face 모델 캐시 위치 |
| `mossSource` | 공식 MOSS-Audio 코드 위치 |
| `allowedOrigins` | 접속할 앱의 정확한 출처. 기본은 공식 Pages와 로컬 개발 서버다. |

설정을 바꾸면 작업이 끝난 뒤 `local-analysis\stop.ps1`로 종료하고 `start.ps1`로 다시 실행한다.
종료 스크립트는 이 설치에서 시작한 프로세스인지 검사하고 진행 중인 작업이 있으면 종료하지 않는다.
OpenRouter를 사용하려면 **저장소 루트의 `.env`**에 다음 값을 넣고 서비스를 다시 시작한다.

```dotenv
OPENROUTER_API_KEY=발급받은_키
```

서비스는 실행 디렉터리와 관계없이 이 파일을 읽으며 `.env`는 Git에서 제외된다.
`OPENROUTER_API_KEY`가 있으면 **OpenRouter의 `google/gemini-3.8-flash`**를 우선 사용한다.
서비스 환경 변수는 `.env`보다 우선하고, `.env`는 설정 파일보다 우선한다.
Google 직접 연결 키는 설정 파일, `.env`의 `GEMINI_API_KEY` 또는 **서비스 프로세스의** 같은 이름 환경 변수에 넣는다.
양쪽 키가 모두 없으면 로컬 분석만 사용한다. 키를 다른 설정 파일에 자동 복사하지 않는다.
키를 브라우저 입력창·저장소·대화에 넣지 않는다. 서비스는 API 키를 프런트엔드에 반환하지 않는다.
모델 프로세스에도 두 API 키를 전달하지 않는다.

## 분석 방식과 결과 해석

- 원본 바이트는 그대로 보관한다. 분석·편집용 PCM은 48kHz/16bit 스테레오로 만들고 수신 샘플 기준 0초부터 정규화한다. 방송의 fMP4 절대 시각 때문에 앞에 긴 무음이 붙는 문제를 피한다.
- 60초 중심 구간마다 앞뒤 30초를 더한 최대 120초 창을 사용한다. 창들이 겹치더라도 각 중심 구간은 한 번만 결과에 반영한다.
- **Qwen3-ASR-1.7B**가 한국어 멘트를 전사한 뒤 프로세스를 종료한다.
- **MOSS-Audio-4B-Instruct**가 음악·멘트·기타와 시간 경계를 분석한다. 성악은 음악으로 취급하고 악장 사이 쉼만으로 자르지 않도록 지시한다. 별도 프로세스로 실행하여 두 모델을 동시에 GPU에 적재하지 않는다.
- 로컬 곡 정보는 근거 멘트와 독립 ASR 전사의 일치를 검사한다. 근거가 없는 필드는 빈 값으로 남긴다. ‘소리만 듣고 특정 연주자를 맞히는’ 기능이 아니다.
- 정형적인 ‘다음 곡은 …’, ‘… 연주였습니다’ 멘트는 전사에서 직접 추출한다. 앞 곡 종료 소개와 다음 곡 소개를 구분하며, 외국 인명은 임의로 교정하지 않고 확인 대상으로 표시한다.
- 해석 불가능한 경계는 겹치는 120초 창 전체 대신 중심 구간(최대 60초)만 Gemini로 보낸다. 경계 보완에는 파일당 음성 한도의 최대 40%, 최대 4회를 배정하여 곡 정보 교정 분량을 남긴다.
- 곡 정보는 최대 6곡씩 소개 멘트 전사와 짧은 음성 발췌를 함께 보내 교정한다. 겹치는 발췌는 합쳐 중복 전송하지 않는다. 음성 잔여량이 부족하면 새 음성 전송 없이 전사 텍스트로 교정하며, 이 경우도 API 호출 횟수와 토큰 비용은 발생한다.
- 가사·방송국 안내를 곡 정보로 채택하지 않고, 이미 채워진 잘못된 후보도 교정한다. 슈베르트 문맥의 ‘도시 번호’는 도이치 작품번호로 정리한다. 인명은 원문 발음과의 대응도 검사하여 전사에 없는 다른 연주자·악단으로 교체하는 것을 줄인다. 이는 외부 음반 DB를 통한 신원 확정은 아니다.
- **곡 정보만 재검토**는 원본·곡 경계를 유지하고 메타데이터와 FLAC 태그만 교정한다. 직접 수정한 곡은 보호한다. 이전 자동 후보, 필드별 원문 근거, 교정 응답을 PC 작업 폴더에 보존한다. 정보가 모두 채워져도 ASR와 모델의 일치만으로 자동 확정하지 않는다.
- Gemini가 제안한 정보는 **확인 필요** 상태로 둔다. 짧은 앞뒤 첨부만으로 전체 음악 경계나 같은 연주인지 자동 확정하지 않는다. 경계 수정은 원본 기준 초를 직접 입력한다.
- 모델이 완전한 구간 목록을 반환하지 못하면 미분리 구간을 따로 표시한다. 실패를 ‘음악 없음’으로 숨기지 않는다.

실제 곡 경계·곡명·연주자 정확도는 방송별로 확인해야 한다. 공식 선곡표 대조·음원 지문 조회는 아직 포함하지 않는다.
공연 실황, 진행자의 음악 위 멘트, 소개 없는 연속곡은 자동 분리가 불완전할 수 있다.
분리 파일은 **FLAC**이며 `TITLE`, `COMPOSER`, `ARTIST`, `PERFORMER`, `TRACK`, `COMMENT` 태그를 기록한다.
압축 방송을 FLAC으로 저장해 원본에 없던 음질이 생기지는 않는다.

## 운영·비용·복구

녹음에는 기존과 동일하게 **앱 실행 + TIMER ON**이 필요하다. PC 분석 서비스도 켜져 있어야 한다.
PC로 전송한 뒤에는 브라우저를 닫아도 분석은 계속된다. 서비스가 꺼져 있으면 브라우저의 원본을
보관하고, 다시 연결하거나 앱을 다시 실행할 때 자동으로 전송을 시도한다.
브라우저 저장 공간이 부족해 원본을 저장하지 못했다면 기존 다운로드 안내를 따라 직접 보관한다.

이미 받은 녹음은 UUID로 구분해 재전송·중복 분석을 막는다. 처리 중 서비스가 꺼지면 원본을 남기고
오류 상태로 바꾸며 **다시 분석**으로 재개한다. 이때 과거 Gemini 사용량을 초기화하지 않는다.
키가 없거나 모델 설치·GPU 실행 자체가 실패하면 방송 전체를 클라우드로 넘기지 않는다.
네트워크/API 오류는 자동 재호출하지 않는다. 요청 전에 사용량을 기록하므로 실패한 요청도
전송량 상한에 포함한다. 각 파일당 **10회 + 전송 초 상한**을 모두 적용한다.

앱 내부 제한은 ‘파일당 음성 전송 한도’ 또는 ‘파일당 Gemini 호출 10회’로 표시한다. API 제공자의 HTTP 429 요청 제한 및 OpenRouter HTTP 402 결제·크레딧 오류와 구분한다. 재검토 시에도 기존 사용량은 초기화하지 않는다.

2026-09-05 실제 ‘명연주 명음반’ 녹음의 메타데이터 교정에서 ‘도시 번호 850’를 `D. 850`, ‘아르카디 모로도스’를 ‘아르카디 볼로도스’로 수정했다. 작품·연주자 조합은 [Sony Classical의 해당 음반 정보](https://www.sonyclassical.com/releases/releases-details/arcadi-volodos)와 대조했다. 이 사례가 다른 인명의 정확도나 곡 경계 정확도를 보장하지는 않는다.

`Gemini 전송 초`는 청구 토큰의 근사 지표이며 토큰 비용을 보장하는 예산 한도는 아니다.
실제 API 응답의 `usageMetadata`(Google) 또는 `usage`(OpenRouter, 반환된 토큰·비용 포함)를 작업 JSON에 저장한다.
호출한 제공자와 모델도 기록하며 OpenRouter 제공자 자동 재시도는 끈다. 키 미등록 상태에서는 API 호출 비용이 없다.

작업 폴더에는 원본(`original.bin`), 편집용 PCM(`source.wav`), 곡 파일, `job.json`, 모델 입력·출력 및 로그가 남는다.
자동 삭제는 하지 않는다. PCM만 시간당 약 0.69GB이므로 상시 운영할 때 보관 기간과 저장 공간을 관리해야 한다.
삭제하려면 필요한 원본·곡 ZIP을 보관한 뒤 서비스가 처리 중이지 않은 해당 작업 폴더를 직접 정리한다.
기본 업로드 제한은 파일당 1GiB, 분석 길이 8시간, 업로드 시작 시 디스크 여유 8GiB다.

### 이 PC의 실제 추론 확인 (2026-09-05)

RTX 4080에서 한국어 합성 소개 + 바흐 첼로 44초 샘플의 전사, 음악 구간, 곡명·작곡가·연주자 태그 저장을 확인했다.
이 샘플의 모델 추론은 ASR 약 3.2초, MOSS 약 11.1초였고 모델 적재·파일 변환 시간은 제외했다.
MOSS의 PyTorch 최대 할당 메모리는 약 10.4GiB였다. 음악 시작 경계는 수작업 구성 시점과 약 0.9초 차이가 있어 정밀 편집이 필요할 수 있다.

KBS 1FM 실제 3분 녹음도 API 업로드·작업 큐를 거쳐 두 음악 구간으로 분리했다.
음악만 있는 구간에서 모델이 곡명을 추측하거나 10초 단위로 나누는 출력이 관찰되어,
전사 근거가 없는 필드·인용을 지우고 이어지는 동일 음악 구간을 합치는 처리를 검증했다.
외국 인명 전사 오류 및 첫 곡의 작곡가 미확인은 그대로 확인 대상으로 남겼다.
